# 資產紀錄：起始樣板（階段 0，尚無資產功能）

由旅遊規劃（stage6）抽出的通用骨架。目前只有「首頁（測試記錄）」與「設定」兩頁，用來驗證框架與備份還原。

## 內容
- 資料層 `js/db.js`：IndexedDB、整庫匯出、合併匯入／完整還原、合併預覽。資料表在 `STORES` 定義，每筆記錄需有 `id` 與 `updatedAt`。
- 主程式 `js/app.js`：hash 路由、手機底部分頁／電腦側欄、設定頁（語言外觀、安裝說明、備份還原、備份提醒、持久儲存）。
- 多語系 `js/i18n.js`（引擎，沿用）與 `i18n/dict.js`（只留通用條目）。
- `sw.js`：網路優先、斷網用快取；只清自己前綴（`at-`）的舊快取。
- `css/style.css`：無印風，原樣保留（仍含旅遊專用樣式，等頁面確定後再瘦身）。
- 圖示：全新設計（深色底＋長條圖），與旅遊規劃不同。

## 與旅遊規劃不衝突的識別字串
| 項目 | 資產紀錄 | 旅遊規劃（對照） |
|---|---|---|
| IndexedDB 名稱 | `asset-tracker` | `trip-planner` |
| localStorage 前綴 | `at-`（`at-lang`、`at-theme`） | `tp-` |
| 快取名稱 | `at-v1` | `tp-v4`、`tp-tiles` |
| 匯出檔 app 識別 | `asset-tracker` | `trip-planner` |
| manifest 名稱與 scope | 資產紀錄，`./`（放在自己的儲存庫路徑下） | 旅遊規劃 |
| 圖示 | 新設計 | 舊設計 |

注意：旅遊規劃的 `sw.js` 目前會刪除「所有不是自己的快取」，會連帶清掉本 App 的離線快取。建議之後把它的 `activate` 改成只刪 `tp-` 開頭的快取（我會另外提供一行修改，由你決定要不要改）。

## 部署
1. 新建一個 GitHub 儲存庫（建議名稱：`asset-tracker`，且**不要用私人資料檔上傳到公開儲存庫**）。
2. 把本資料夾內容（不含外層資料夾）上傳到儲存庫根目錄，Settings → Pages 選 main 分支。
3. 第一次開啟會安裝 Service Worker，要「載入兩次」離線才生效。
4. 沒有資料遷移（全新應用）。

## 實測清單（請在手機與電腦做）
1. 開啟後，首頁按「加入一筆測試記錄」兩次，應顯示 2 筆，並出現「提醒備份」。
2. 設定 → 匯出完整備份：應下載 `資產紀錄_日期.json`；設定頁顯示上次備份時間。
3. 再加幾筆記錄後匯入剛才的檔案，選「合併匯入」：應新增 0 筆、保留你這邊較新的記錄。
4. 首頁清除測試記錄後，匯入該檔案選「完整還原」：記錄應回來。
5. 切換語言（English／日本語）與外觀（淺色／深色），重新整理後仍保留。
6. 載入兩次後開飛航模式重新開啟，應仍可使用。
7. Android：選單 →「安裝應用程式」；iPhone：Safari 分享 →「加入主畫面」。圖示應是深色長條圖。
8. 若同帳號已裝旅遊規劃：兩個 App 各自的資料與語言設定互不影響。
